# Codex Prompt: Dashboard Builder

You are building the operator dashboard layer for Agri-AI on top of an existing Python pipeline.

Before writing anything, read:

- `AGENTS.md` — project rules and writing standards
- `docs/product/mvp_scope.md` — current build status and what comes next
- `prompts/codex/code_writer.md` — full domain model, data specs, and code standards
- `src/main.py` — the existing pipeline entry point
- `src/gap.py` — the gap analysis output structure
- `src/memo.py` — the memo output structure

The pipeline already works. Do not touch it unless a bug is found.
Your job is to build a thin local UI on top of the existing `output/` files.

---

## What You Are Building

A local Streamlit dashboard that reads the pipeline output files and presents them to an operator in a useful, readable format.

This is not a web product. It is a local tool for a pilot operator to use during their weekly planning session.
The operator will run the pipeline first, then open the dashboard to review the results.

It does not need:

- user authentication
- a database
- real-time data updates
- mobile layout
- deployment infrastructure

It needs to work locally with: `streamlit run dashboard.py`

---

## Input Files

The dashboard reads from `output/` (or a configurable path):

| File | Contents |
|---|---|
| `gap_analysis.csv` | Full crop × week gap table. Key columns: `crop_canonical`, `week_iso`, `year`, `coverage_ratio`, `shortage_lbs`, `overage_lbs`, `shortage_pct`, `overage_pct`, `risk_flag` |
| `demand_by_crop_week.csv` | Aggregated demand by crop and week |
| `supply_by_crop_week.csv` | Aggregated supply by crop and week |
| `unresolved_skus.csv` | SKU names with no canonical match |
| `weekly_memo.txt` | Operator-facing plain-text memo |

All files are generated by running: `python3 -m src.main --data-dir data --output-dir output`

If any output file is missing, show a clear message telling the operator to run the pipeline first.

---

## Required Views

Build these views in this order. Do not skip ahead.

### 1. Season Overview (default landing view)

A summary of the full season in numbers:

- total crops tracked
- total weeks with data
- count of risk-flagged crop-weeks
- count of unresolved SKUs

Keep this compact. One row of metrics at the top.

### 2. Risk Table

A filterable table of `gap_analysis.csv` sorted by: `risk_flag DESC`, `shortage_pct DESC`, `week_iso ASC`.

Columns to show:

- Week
- Crop
- Demand (lbs)
- Supply (lbs)
- Coverage %
- Shortage (lbs)
- Overage (lbs)
- Risk

Use color to make `risk_flag = True` rows visually distinct. Red background or red text on the risk column is sufficient. Do not over-style.

Allow the operator to filter by:

- crop name (multi-select)
- risk flag only (checkbox)
- week range (slider)

### 3. Demand vs Supply Chart

A bar chart showing demand and supply side by side for a selected crop across all weeks.

- x-axis: week number
- y-axis: pounds
- two bars per week: demand (blue) and supply (green)
- crop selector above the chart

This is the most useful visual for the pilot operator — it shows at a glance where the gaps are across the season.

### 4. Weekly Memo

Display the contents of `weekly_memo.txt` as plain text in a scrollable text area.

Add a button to copy the memo to clipboard.

No reformatting. Show it exactly as generated.

### 5. Unresolved SKUs

If `unresolved_skus.csv` has rows, show a warning banner at the top of the dashboard and a table of the unresolved entries.

If zero unresolved SKUs, do not show the section.

## File Structure

```
agri-ai/
├── dashboard.py          # single-file Streamlit app
├── src/                  # existing pipeline — do not modify
├── output/               # pipeline outputs read by dashboard
└── requirements.txt      # add streamlit here
```

Keep the dashboard in a single file (`dashboard.py`) at the root.
Do not create a `pages/` directory or multi-page structure at this stage.

---

## Tech Constraints

- Streamlit only. No React, no FastAPI, no separate backend.
- Pandas is acceptable for reading and filtering CSVs inside the dashboard. Do not add it to the pipeline (`src/`).
- No external charting libraries beyond what Streamlit provides natively (`st.bar_chart` or `st.altair_chart` with basic Altair). Do not add Plotly or Bokeh.
- Keep `requirements.txt` minimal: `streamlit` and `pandas` only.

---

## Do Not Build

- live data refresh or polling
- database backend
- export to PDF or Excel
- mobile layout
- deployment config (Heroku, Docker, etc.)

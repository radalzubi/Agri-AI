# Codex Prompt: Dashboard Builder

You are building the operator dashboard layer for Agri-AI on top of an existing Python pipeline.

Before writing anything, read:

- `AGENTS.md` — project rules and writing standards
- `docs/product/mvp_scope.md` — current build status and what comes next
- `prompts/codex/code_writer.md` — full domain model, data specs, and code standards
- `src/main.py` — the existing pipeline entry point
- `src/gap.py` — the gap analysis output structure
- `src/memo.py` — the memo output structure

The pipeline already works. Do not touch it unless a bug is found.
Your job is to build a thin local UI on top of the existing `output/` files.

---

## What You Are Building

A local Streamlit dashboard that reads the pipeline output files and presents them to an operator in a useful, readable format.

This is not a web product. It is a local tool for a pilot operator to use during their weekly planning session.
The operator runs the pipeline first, then opens the dashboard to review results.

It does not need:

- user authentication
- a database
- real-time data updates
- mobile layout
- deployment infrastructure

It needs to work locally with: `streamlit run dashboard.py`

---

## Input Files

The dashboard reads from `output/` (configurable via a sidebar path input):

| File | Key columns |
|---|---|
| `gap_analysis.csv` | `crop_canonical`, `week_iso`, `year`, `coverage_ratio`, `shortage_lbs`, `overage_lbs`, `shortage_pct`, `overage_pct`, `risk_flag` |
| `demand_by_crop_week.csv` | `crop_canonical`, `week_iso`, `year`, `total_demand_lbs` |
| `supply_by_crop_week.csv` | `crop_canonical`, `week_iso`, `year`, `total_supply_lbs` |
| `unresolved_skus.csv` | `buyer`, `crop_raw`, `quantity_lbs`, `week_iso`, `year`, `crop_canonical` |
| `weekly_memo.txt` | plain text |

All files are generated by: `python3 -m src.main --data-dir data --output-dir output`

If any output file is missing, show a clear message instructing the operator to run the pipeline first. Do not crash.

---

## Required Views

Build in this order. Do not skip ahead.

### 1. Season Overview (default landing view)

A compact summary row at the top of the page:

- total crops tracked
- total weeks with data
- count of risk-flagged crop-weeks
- count of unresolved SKUs (show in orange if > 0)

### 2. Risk Table

A filterable, sortable table of `gap_analysis.csv`.

Default sort: `risk_flag DESC`, `shortage_pct DESC`, `week_iso ASC`.

Columns to show: Week, Crop, Demand (lbs), Supply (lbs), Coverage %, Shortage (lbs), Overage (lbs), Risk.

Use color to distinguish `risk_flag = True` rows — red text or highlight on the Risk column is sufficient.

Filters above the table:
- crop multi-select
- show risk only (checkbox, default off)
- week range slider

### 3. Demand vs Supply Chart

Bar chart showing demand and supply side by side for a selected crop across all weeks.

- x-axis: week number
- y-axis: pounds
- two bars per week: demand (blue) and supply (green)
- crop selector above the chart

This is the most useful visual for the pilot — it shows at a glance where the season gaps are.

### 4. Weekly Memo

Display `weekly_memo.txt` as plain text in a scrollable text area.

Add a copy-to-clipboard button.

Do not reformat the memo content. Show it exactly as generated.

### 5. Unresolved SKUs

If `unresolved_skus.csv` has rows, show a warning banner and a table of the entries.

If zero unresolved rows, do not show this section at all.

## File Structure

```
agri-ai/
├── dashboard.py          # single-file Streamlit app — create this
├── src/                  # existing pipeline — do not modify
├── output/               # pipeline outputs read by dashboard
└── requirements.txt      # add streamlit and pandas here
```

Keep the entire dashboard in one file: `dashboard.py` at the repo root.
Do not create a `pages/` directory or multi-page Streamlit structure.

---

## Tech Constraints

- Streamlit only. No React, no FastAPI, no separate backend process.
- Pandas is acceptable inside `dashboard.py` for reading and filtering CSVs. Do not import it inside `src/`.
- Charts: use `st.bar_chart` or basic Altair via `st.altair_chart`. Do not add Plotly or Bokeh.
- `requirements.txt` should contain only: `streamlit` and `pandas`.
- Standard library for everything else.

---

## Do Not Build

- user login or auth
- live data refresh or file watching
- database backend
- PDF or Excel export
- mobile layout
- deployment config (Heroku, Docker, etc.)
- multi-page Streamlit structure
